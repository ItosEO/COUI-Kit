# Agent Note: MPL 2.0 与独立名称政策

Status: implemented

## Problem

仓库没有项目级许可证，维护者希望自有代码使用 MPL 2.0，同时明确禁止未经授权的分叉发行名称包含 COUI-Kit，并限制项目 Logo 和易混淆标识的使用。将名称限制直接作为源码许可的额外条件，会混淆代码权利与品牌使用边界。

## Decision

根目录 [LICENSE](../../../../LICENSE) 保留 Mozilla 发布的标准 MPL 2.0 文本，不追加自定义许可条款。[NOTICE](../../../../NOTICE) 应用标准源码许可通知，说明自有源码范围与第三方例外；使用 MPL Exhibit A 允许的目录级通知，不批量改写既有源码头部。

[名称与标识政策](../../../../TRADEMARKS.md) 独立维护发行名称与 Logo 规则：未经书面授权，修改版、分叉版和衍生项目的发行名称不得包含 COUI-Kit，不区分大小写；保留对其他易混淆标识和虚假官方关系的限制。必要的版权、许可、来源及真实兼容性说明不受此限制，源码包名和 API 标识不被一并视为发行品牌。

名称政策仅涉及本项目依法享有的权利，不改变 MPL 授予的代码权利，也不主张对既有 COUI 名称的独占。Skia 文件头部与 BSD 原文保持原样，其他第三方材料沿用其适用条款，不将来源尚未核验的内容视为已获重新许可。

README、库模块说明、接入指南和贡献指南引用上述事实来源。本次只建立许可与名称约定，不配置发布、GPG 或仓库公开状态。

## Alternatives considered

- **把名称禁用规则写进 MPL 正文。** 规则集中，但会改变标准许可文本，并可能额外缩减源码接收者权利；代码许可与名称政策分开维护。
- **只禁止容易混淆的名称。** 可以覆盖品牌误认，但边界不够明确；维护者要求将包含 COUI-Kit 的发行名称单独列为禁用情形，同时保留混淆规则兜底。

## Consequences

[库预览发布](2026-10-25-github-packages-preview.md)将现有声明装入源码与 API 文档归档，不改变本篇的许可和名称边界。

接入者可以分别确认代码许可与分叉发行的品牌限制，代价是维护者需同步维护两种边界。新增第三方内容时同步 NOTICE；新的名称或 Logo 授权需要明确书面范围。标准许可文本不因项目政策调整而变化。

本决定不证明名称权属或第三方授权已完成核验，也不把名称政策当作独立的源码许可终止条件。发行前的来源核对仍需按实际材料完成。

验证限于标准许可原文一致性、既有 Skia 声明保留、文档链接、编码、Note 与差异检查；不需要 Android 构建或设备验证。
