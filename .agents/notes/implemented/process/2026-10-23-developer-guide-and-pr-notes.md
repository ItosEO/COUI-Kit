# Agent Note: 官方对齐、Developer 指南与 PR 笔记流程

Status: implemented

## Problem

独立库需要可随仓库交付的开发规范和关键取舍。只保留聊天或外部宿主路径会使后续开发者重复采用已否定算法、误改已批准特化，或在没有效果证据时声称原厂一致。

ChipTab 的审查还暴露了流程缺口：公式、终点和参数检查不能覆盖手势调用链。未进入拖动的抬手、父容器接管，以及不同回弹入口的积分状态差异，都需要从原厂入口追到退出与再次进入，不能用检查数量替代。

## Decision

[Developer 指南](../../../../docs/development/README.md) 提供开发入口，[开发流程](../../../../docs/development/workflow.md)持有开发与评审契约，AGENTS 持有执行权限，组件与效果使用页持有装配契约，代码/构建配置持有参数。新增 COUI 能力要求以指定官方版本为基准，效果至少 1:1，尽可能采用相同算法、执行顺序和运动语义；无法等价的公开承载差异必须明确。

分层、渐进卷积、普通阴影、菜单会话与层序、顶栏搜索、滑条等决定在本仓库独立维护。阴影合并原网格和后续 clipShader 决定；搜索合并槽位捕获、兄弟透明前景和焦点边界。历史 Note 保留首次决定日期、原厂材料、重要备选和验证限制，不复制外部业务规范、本机绝对路径或设备数据，也不自动修改外部宿主依赖。

[实现分析与复刻指南](../../../../docs/development/replication-guide.md) 持有证据追踪方法、典型链路和排错经验。Developer 提供 README、公开装配、接入、兼容要求、复刻指南和核心 Note 的任务导航。现行说明不以原宿主为使用或开发前提；历史来源使用原宿主称谓，原厂符号与材料标识保留。

[开发与评审流程](../../../../docs/development/workflow.md) 明确五个阶段：固定目标与证据、对照行为与分支、实现完整链路、完成后的双向核查，以及反例验证与 PR 交付。流程由 Developer 持有，复刻指南解释操作方法；PR 模板只收集对照依据与结果，不复制整套流程。

新增组件先检查效果目录、基础实现和已有消费者。符合原厂目标的后端必须复用；能力不足先评估公共 effect 的最小扩展，确需新实现时在 Note 和 PR 说明候选、实际缺口与原厂依据。AGENTS 要求先读此规则，评审检查重复算法及公共扩展对已有消费者的影响。复用不混同不同原厂算法，也不跨节点共享可变 renderer。

双向核查既查原厂路径有无遗漏，也查移植代码新增的状态重置、裁剪或回调有无依据。主实现者亲自读取核心代码，审查范围包含共享实现与调用方，不只看 diff。含输入和动画的组件在所属 Note 记录受影响路径，不为每次核查新建报告或长期测试框架。

ChipTab 案例链接到[输入中断记录](../bug-fix/2026-10-24-chip-scroll-interruption.md)：按原厂分发补齐未拖动的释放路径，按子项取消处理核对按压，再按 `setCurrentValue`、`setAtRest` 与 `notifyEdgeReached` 区分状态更新。终止和方向检查仍有价值，但不能独立支撑原厂一致的结论。原厂源码逐路核对与同输入执行对照分别记录，不将前者写成运行验收。

项目级安装 write-notes-like-deepseek Skill、参考文档、模板和脚本，团队不依赖个人安装。仓库规则及用户授权优先，通用确认流程不产生重复审批。非平凡变更检索历史后更新或新增 Note，与实现同一个 PR；纯机械修改不立 Note。

Skill 要求 Note 正文使用简体中文，确无真实备选时允许在备选节写“无”，每次修改 Note 后执行校验。校验器兼容尖括号链接、额外中文节名，并排除归档目录根部的 AGENTS；看板保留多段章节内容，同日按稳定 id 排序，抽屉打开时锁定背景并重置内容滚动。

PR 模板要求官方依据、API 影响、Note、实际检查和待验收项；变更通过功能分支与 PR 进入 main。Note CI 使用 Node 类型擦除执行已有静态校验器，无需 npm 安装。Android 检查与按需打包由 [Demo 签名与 CI](../../proposed/process/2026-10-25-demo-signing-ci.md) 扩展，库发行仍暂缓。远端保护由维护者配置，本地文档不能代替服务端强制设置。

## Alternatives considered

- **只链接个人 Skill 或外部宿主路径。** 文件少，但其他开发者克隆后无法独立执行，也难以判断库适用边界。
- **原样复制整个 SPEC 与全部 Note。** 历史完整，却混入 Binder、服务和业务约束；只迁入仍约束当前实现的决定。
- **只有“必须写 Note”的文字要求。** 接线最少，但格式、状态和归档封印容易失效；复用脚本检查结构，语义和效果留给评审。
- **只在复刻指南追加检查项。** 文档改动少，但不能说明开发者何时检查、评审者凭什么判断；Developer 持有流程，指南提供方法与案例。
- **用更多数值场景代替事件路径核查。** 易于自动运行，却仍可能只覆盖正常释放。先选择能暴露路径差异的反例，再按需要扩展数值范围。

## Consequences

[普通文档分层](2026-10-25-documentation-audiences.md) 调整文档位置与阅读入口，保留本篇的原厂对齐、评审与 Note 流程。

团队可在仓库内阅读与验证同一规则，代价是契约改变时同步对应文档。文档独立维护，不与外部宿主自动同步，也不能按旧快照改回当前参数。新规范不撤销已有批准特化。

按路径对照增加了审查工作，但能区分物理算法、输入接管和 Compose 装配的不同问题。结构脚本继续只校验可机械判断的内容，不增加宣称“官方一致”的自动门禁。Android 构建、设备输入、视觉与性能仍按仓库权限执行，未验收项目在交付时保留。

建立规范时执行了本地 Note、文档链接、编码、workflow YAML 和差异检查，未运行 Android 或远端工作流。这些历史结果不代替后续修改的验证。
