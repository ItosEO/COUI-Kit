# Agent Note: 顶栏搜索的右侧融合动作

Status: implemented

## Problem

顶栏搜索需要一个随搜索展开而分离、随关闭而融合收回的自定义动作。独立按钮的横向显隐只改变布局和透明度，不能产生连接两部分材质轮廓的融合区域。

## Decision

TopAppBarSearch 的可选 action 槽只承载文字、图标和排版，onActionClick 承载业务操作。组件持有按钮点击、禁用语义、反馈和胶囊材质，宿主不再叠加独立按钮表面。原有 TopAppBarSearchAction 继续管理工具栏中的常驻或退场动作，两者职责不同。

搜索与融合动作由同一绘制节点持有真实 pair renderer、两个内容层和采样坐标，复用 couiFloatingPair。两部分使用已完成渐进处理的顶栏背景及前景合成，按动作在下、输入在上的顺序绘制和放置；不复制 Shader，也不引入第三个虚构主体。每个独立节点的 renderer 不与搜索入口或其他搜索实例共享。

融合动作使用既有搜索弹簧的当前进度，关闭沿同一几何路径反向。搜索自身仍按点击中心向展开端点移动；节点保留到现有搜索收尾完成。即时反向继续使用弹簧的当前位置和速度，重新点击入口仍由既有 finishCollapse 交接。右侧动作几何是用户要求的项目扩展，融合后端继承原有实现；不将新路径称为原厂顶栏已有行为。

自定义动作先测量，随后按其真实宽度排版输入；不通过 onSizeChanged 回写布局尺寸。动作宽度限制给输入保留空间。绘制、输入放置和 RTL 镜像共用同一帧几何。输入按最终宽度排版，再按当前主体裁剪，完整 BasicTextField 承担胶囊中的留白命中，防止重叠区穿透至动作。

graphicsLayer 的属性块也会在节点挂载和语义计算时执行，不能假定它晚于测量。几何尚未建立时，两层保持透明，不读取几何；首次测量发布真实几何后再参与显示与输入定位，不用预估尺寸代替实际内容测量。

关闭或隐藏立即停止动作输入并移除其语义，融合绘制继续收尾。onActionClick 为空表示禁用动作，enabled 控制搜索与动作；业务是否接受关闭、是否清空查询及何时收起键盘仍由宿主决定。没有 action 的调用继续使用原有单主体后端。

## Alternatives considered

- **TopAppBarSearchAction 加普通显隐动画。** 可复用已有按钮，但只有移动、缩放和透明度，没有材质融合，不能满足分离和收回要求。
- **让宿主在 action 中放完整 TopAppBarButton。** 保留独立按钮用法，却会重复材质、投影、点击所有者，并使融合几何与输入脱节。
- **用同色 Metaball 遮罩包两个独立按钮。** 可生成连接轮廓，但不能还原现有双主体的背景采样、材质和光效分层，重复了成熟后端的职责。

## Consequences

组件增加双主体内容录制和按内容分阶段测量的成本，获得真实的材质融合及一致的输入几何。普通用法见[顶栏搜索](../../../../docs/components/search.md#从搜索胶囊分离自定义按钮)，实现见[双主体装配](../../../../coui/src/main/java/com/itos/coui/topappbar/TopAppBarSearchPair.kt)。

静态检查和几何数值检查只能覆盖尺寸、镜像、路径与现有融合核参与，不能证明 Android GPU 像素、IME、TalkBack 或触摸事件的实际结果。设备动画中段、快速反向和隐藏恢复仍需用户验收。
