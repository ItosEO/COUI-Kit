# Agent Note: 胶囊分段指示器与受控提交

Status: implemented

## Problem

宿主需要胶囊内共享指示器的分段选择。ChipTab 的每项独立材质和横向滚动不能表达这一布局。原厂还同时存在普通填色和透明材质的用法；只有透明材质的组件会要求普通 Group 场景也提供背景采样源。

## Decision

[SegmentedControl](../../../../coui/src/main/java/com/itos/coui/segmentbutton/SegmentedControl.kt) 持有布局、指示器和一个输入 owner。标签、选中索引和提交归宿主；默认即时提交，抬手提交是明确的项目选项。延后模式中的取消不提交草稿，即时模式中的已提交选择不回滚。业务未接受选择时，收尾后回到宿主值。

可空 backdrop 同时表达是否需要背景采样。省略时直接绘制容器与指示器，不创建模糊、轮廓和跟手光资源；传入时复用 CouiFloatingRenderer 的单主体材质、模糊与轮廓。普通填色的预设仍保留透明度，“不透明”不表示颜色 alpha 必须为 1。每个透明节点持有独立 renderer，宿主可在工厂中捕获创建失败并显示错误 UI，不能跨节点共享有状态的渲染实例。

位置、宽度、高度、橡皮筋复用 CouiSpring，按压和形变复用公共 Motion。普通弹簧只补充可选的 AndroidX 积分边界，默认仍无界；指示器的中心范围、增长宽度上限及高度下限进入积分器，不能只把超界结果裁在绘制端。重新按住或切换项目时从当前可见中心接续，避免丢失回弹偏移。没有复制另一套弹簧或材质 Shader。

指示器以浮点矩形在容器之后、标签之前绘制，运动帧不重新测量标签。指示器自己的径向投影属于该组件的专属原厂绘制，不使用外部浮动投影代替。普通填色采用 Path 几何，容器裁剪覆盖指示器及其投影，对应原厂 drawSmoothRoundRect 的 Path 分支。透明模式的 CAPSULE_10 轮廓复用 CouiContour；跟手光直接混合到已经绘制的材质和指示器，不写入透明标签层。光源输入与这一绘制阶段共用形变后的内容坐标，避免平移和缩放被重复施加。

输入统一驱动公共 Motion。横向滑选越过阈值后持续持有手势，手指的纵向偏移不触发父页面滚动；确认滑选前的纵向手势仍交给父容器。父级提前接管、系统 CANCEL、多指切换、禁用和节点移除结束交互，取消阻止新的业务提交。点按非选中项在 UP 请求选择，从选中项或移动中的指示器起拖才能滑选。焦点有可见反馈，标签保留激活和选中语义；RTL 同时映射几何和命中。

原厂 `isInsideView` 只在拖动时扣除切换距离，让经过项目边缘的手指继续当前选择。Compose 使用同一组累计取整的边界测量标签、绘制指示器和判断命中，避免逐项取整后最后一项被父约束截短。拖动阈值使用窗口坐标，命中使用形变后内容的局部坐标。

文字自然宽度随字体解析结果更新，与标签显示使用同一字体。尺寸由预设与父约束共同决定，实际受约束高度同时进入绘制和命中。公开用法和预设见[分段选择器文档](../../../../docs/components/segmented-control.md)。

## 原厂依据与适配边界

基础对照为 Settings 17.0.0 中的 COUISegmentButtonLayout、SegmentButton / Tiny、COUIMaterialBlurEffect 与 COUIMaterialStrokeEffect。初始实现样本的 APK SHA-256 为 d97df8a9227520a6f673e5d6f5efbc901b5d9d4c501d12e5d8bf717daae079d5；补充的 PJZ110 Settings 来自另一设备，不能视为同一构建。精确常量和反编译控制流需结合对应 DEX 核对，素材不进入库的运行依赖。

原厂宽度分配、指示器运动和命中共同决定几何及手势，不能仅按圆角截图调参。普通与紧凑尺寸保留各自的回弹与宽度余量。透明模式选择 CONTENT_SEGMENT_BUTTON 和 CAPSULE_6；指示器使用 CAPSULE_10 并关闭其内晕投影，保留独立渐变投影。

亮色透明容器沿用[菜单的描边颜色算法](../../../../coui/src/main/java/com/itos/coui/effect/CouiEdge.kt)。以分段选择器的模糊材质为颜色参考，等比例收回过亮的描边，并以内晕覆盖率混色，避免亮色边缘叠成白边。胶囊的光效范围仍由分段选择器的距离场决定。

独立应用样本只证明对应入口的用法。相机 7.006.123 的设置页显式启用材质；电池 1.3.7 的两个统计页消费者没有启用调用，且组件构造关闭材质用户开关，其普通绘制分支作为默认填色依据。相册 17.10.41 的水印页启用材质并另行设置模糊、轮廓和指示器参数，这些定制值不作为通用预设。各应用 DEX 与系统 Java 接口样本不保证来自同一构建，资料中也没有 native 渲染实现，不能据此推断所有设备的最终外观。

公开 API 34 的浮动后端承担背景采样与 GPU 合成；没有移植 OEM 响应式栅格、多页 ViewPager 回调、特权材质开关或专用振动波形。跨平台触感使用公开 HapticFeedback。动画和材质的真机中间帧、RTL、父滚动接管、TalkBack 及性能仍需按同一原厂版本验收，构建与静态对照不构成 1:1 结论。

## Alternatives considered

逐帧改变一个子布局的宽高容易复用背景 Modifier，但会持续测量指示器，并把浮点物理量提前取整；采用绘制矩形及稳定标签布局。

用同色背景源统一走透明材质可以只维护一条绘制路径，但仍承担采样资源，并让普通填色经过材质变换。普通分支直接绘制，两种外观共用布局、选择会话与指示器运动；透明分支继续装配已有公共后端。

只在画面上裁剪弹簧超界值能少改公共通道，却让内部位置、速度和反向时间继续沿越界路径积分，因此给公共通道增加默认无界的可选 min/max，而不是新增组件专用物理引擎。

## Consequences

分段选择能在本库和 Demo 中独立使用，宿主持有提交且无需携带业务材质层。代价是组件维护两条容器绘制路径，每个实例持有四路指示器弹簧，透明节点另持有独立浮动资源并需要不含自身的背景源。两种外观均保留 API 34 要求。性能、视觉及输入中断仍需真实设备验证；若需支持更低 API，应独立检查公共绘制和输入依赖，不能仅放宽注解。
