# Agent Note: 悬浮操作栏的绘制与动画归属

Status: implemented

## Problem

便签编辑页有多个外形相似的工具区。主编辑栏整栏显隐、块级内容操作栏退场以及单个菜单组的图标增删分别由不同对象控制。只对照其中一个弹簧参数，无法确定另两种操作的可见性和绘制边界。

## Decision

图标增删参考 PLK110 便签 17.0.30 的手机编辑主栏，编辑器将动作交给同一个 COUIBottomFloatingToolbar 菜单组。整栏显隐复用公共缩放显隐效果。翻译 17.3.4 将显隐模糊施加在菜单前景，与玻璃材质的后景采样分开。输入跟随目标可见性，绘制保留到缩放、透明度和前景模糊全部结束。

列表以动作 ID 提交结构变化。正在退出的动作保留上一份绑定，后续批次等待本批完成。ItemViewAnimatorImpl 在退出项所在位置施加负间距，再根据首尾项的坐标和缩放求材质边界；同一组浮点坐标用于内容、命中和胶囊。

[悬浮操作栏](../../../../coui/src/main/java/com/itos/coui/floatingtoolbar/FloatingToolbar.kt) 共用一个单主体浮动表面、跟手光和按压形变。默认材质取编辑主栏的底栏预设，图标自行提供内容和配色。单项处理轻点。胶囊与导航底栏共用拖动处理，超过触摸阈值时接管移动，使父容器保持原位。

## Alternatives considered

- 分别为图标和整栏宽度做补间会产生两套几何。尤其在删首项、删末项和弹簧超调时，逐槽取整的宽度总和会偏离原厂首尾边界。
- 用顶栏胶囊材质加大模糊半径，会保留顶栏的混色顺序和描边预设。底栏已有相同的材质后端。
- 便签主编辑栏的 f0 在退场首帧清空透明度，会使用户看不到缩小过程。

## Consequences

宿主控制业务动作、正文和键盘避让，组件内置处理可点击系统栏安全区与悬浮边距。首次绑定直接呈现；后续操作列表可清空或从空恢复，沿用同一批次动画。原厂适配器的全量空绑定会被底层控件拒绝，主编辑栏另有独立显隐入口。原厂私有系统材质服务与公开 Android 绘制后端分别运行，设备画面仍需在相同主题和系统效果设置下核验。
