# Agent Note: Scaffold 管理正文源，独立组件保留显式接入

Status: implemented

## Problem

宿主已经选择 COUI Scaffold 时，重复创建源、挂载正文节点和传递参数增加装配成本。第三方容器又需要保留原有的显式采样路径，不能为了便利而强制替换页面容器或引入全局初始化。

## Decision

COUI Scaffold 管理本实例的正文源，录制完整正文视口与容器底色。顶栏、底栏和浮动操作通过局部作用域读取默认源；显式传入的源仍优先。背景源和内容录制继续复用 backdrop 后端，不改变模糊、材质或融合算法。

默认源只提供给正文之外的独立槽位，不能提供给被采样的正文子树。否则正文内新增一个默认采样消费者，就会把自身录入源。正文中的 ChipTab、预览和独立模糊面板继续分离自己的源与消费者；菜单和材质弹窗需要完整窗口源，不由正文源替代。

浮动操作槽使用 BoxScope 内容，可以放单个 FAB，也可以用 Column、Row 或 Box 组合多个。容器只统一避让栏位与安全区；排列、间距、重叠层级和动作由宿主决定，不增加展开菜单或分组控制器。多个 FAB 共享正文源，各自持有独立 renderer，并且全部位于采样树之外。

容器底色进入正文采样节点，横向安全区在外层单独补色。这让空白正文也有完整背景，并避免半透明底色在同一区域重复绘制。嵌套 Scaffold 各自创建源，显式参数及第三方容器的接入条件保持不变。

## 与既有决定的关系

[可选页面容器](2026-11-03-optional-coui-scaffold.md)和[宿主页面所有权](2026-11-03-host-owned-page-layout.md)部分重叠：本篇取代 COUI Scaffold 不管理采样、不提供浮动操作槽的限制，保留可选容器、独立主题、显式 Insets、滚动和业务所有权。第三方容器仍使用创建源、挂到正文、显式传入的三处连接。

[二级页组件](../feature/2026-11-01-secondary-page-primitives.md)部分重叠：其搜索、折叠、正文补偿和输入职责继续成立，页面源改由所选容器决定。使用说明由[页面容器](../../../../docs/components/scaffold.md)和[背景采样](../../../../docs/effects/backdrop.md)持有。

## Alternatives considered

- 所有容器都显式装配源，接口最少，但 COUI 页面也要重复传递已有布局边界可以确定的依赖。
- 在整个 Scaffold 子树提供正文源，代码更短，但正文内的默认消费者会采样自身。
- 将多个 FAB 改成数据列表，容器可以统一排版，却限制自定义内容与重叠方式；保留组合槽位。
- 自动安装完整窗口源可以继续减少参数，但会扩大录制范围，并混淆正文效果与菜单、弹窗的来源；两者保持独立。

## Consequences

使用 COUI Scaffold 时，独立槽位内的组件无需手动设置 backdrop。使用其他容器或正文内部独立效果时，原显式源接口继续可用。库承担正文录制与作用域的生命周期；宿主仍管理业务、滚动、Padding 和 renderer。

测量与源分层可做静态及替身检查。真实 Insets 传播、GPU 采样、多个 FAB 的重叠输入和设备动画仍需运行 Demo 验收。
